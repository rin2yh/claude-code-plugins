# Claude Code で校正するとき

SKILL.md の手順のうち、Claude Code 固有になる部分だけをここにまとめる。

## ステップ0: 規約ファイルの置き場所

文体・表記の指定は次の順に探す。

- `CLAUDE.md`（リポジトリルート、`~/.claude/CLAUDE.md`）
- `.claude/rules/*.md`（サブディレクトリも再帰的に読まれる）

`.claude/rules/` のファイルは `paths:` フロントマターでスコープされていることがある。校正対象が Markdown なら、`**/*.md` にマッチするルールが効いている。

## ステップ1: 5観点を並列に起動する

Task ツールでサブエージェントを5つ、**同じメッセージ内で同時に**起動する。1つずつ起動すると直列に実行されて時間がかかるうえ、後の観点が前の結果を引きずる。

各サブエージェントへ渡すもの:

- 担当する観点1つ（SKILL.md の「観点1〜5」のうち1つだけ）
- 対象ファイルのパス
- ステップ0で分かったプロジェクトの表記ルール
- SKILL.md の「各観点で共通に守ること」（出力形式や編集禁止など）。**そのまま渡す** —— サブエージェントは SKILL.md を読んでいない

観点4（数字・固有名詞）と観点5（事実確認）を担当するサブエージェントには WebSearch / WebFetch を渡す。他の3つは Read / Grep / Glob で足りる。

サブエージェントには Edit / Write を渡さない。渡さなければ、共通ルールの「編集しない」がツール側でも担保される。

## ステップ3-B: 判断を仰ぐ

SKILL.md の「ステップ3 / B. 判断が要るものは1件ずつ」と「何件を、どの順で聞くか」に従い、提示手段として `AskUserQuestion` を使う。

- 修正後の文そのものは選択肢の `preview` に入れる
- 1回の質問は4件までしか出せない。SKILL.md の「まず重要な3件」という区切り方はこの上限に収まるが、**超える分はツール側の制約として必ず複数回に分かれる**

## ステップ4: 方針の書き残し

決まった表記方針は `CLAUDE.md` か `.claude/rules/writing.md` に残すことを提案する。表記ルールは Markdown を編集するときだけ効けば十分なので、`.claude/rules/` に `paths: ["**/*.md"]` 付きで置く方が CLAUDE.md を膨らませずに済む。

`meta-skills` プラグインを入れているなら、`rule-creator` スキルにそのまま渡せる。
