# Codex で校正するとき

SKILL.md の手順のうち、Codex 固有になる部分だけをここにまとめる。

## ステップ0: 規約ファイルの置き場所

文体・表記の指定は次の順に探す。

- `AGENTS.md`（リポジトリルート）
- 校正対象と同じディレクトリ、またはその上位ディレクトリの `AGENTS.md`（近い方が優先される）
- `~/.codex/AGENTS.md`（全プロジェクト共通）

`AGENTS.md` には Claude Code の `paths:` にあたるファイル種別スコープが無いので、**「Markdown を書くときは」といった適用条件が本文中に書かれていないか**を読み取る必要がある。見出しや前置きで対象が限定されていたら、それに従う。

## ステップ1: 5観点をどう回すか

Codex にサブエージェント相当の並列実行手段があるなら、それを使って5観点を同時に走らせる。無い、または使えるか分からない場合は**観点ごとに順番に回す**。

SKILL.md の「各観点で共通に守ること」は逐次でもそのまま守る。そのうえで、逐次固有の注意が3つある。

- **1つの観点を見ている間、他の観点は指摘しない。** 「ついでに誤字も直す」をやると、観点を分けた意味がなくなる。誤字を探す目と事実確認の目は両立しない
- **全観点が終わるまで1文字も編集しない。** 並列なら書き込み衝突の話だが、逐次では後の観点が修正後の文を見てしまうのが問題。指摘は全部メモに溜めておき、ステップ2でまとめる
- 観点を切り替えるときは、前の観点で見つけたものを一度忘れて頭から読み直す

逐次で回す分、並列より時間がかかる。**それでも観点を混ぜてはいけない** —— 速さのために5観点を1回の通し読みにまとめると、このスキルを使う理由が無くなる。

## ステップ3-B: 判断を仰ぐ

選択肢を提示する専用の UI は使わない前提で、テキストで番号付きの選択肢を出す。件数や中身の決め方は SKILL.md のステップ3-B に従う。

```
表記をどちらに寄せますか。

1. 「〜することができます」→「〜できます」に統一する
   修正後: この設定は後から変更できます。
2. 現状のまま
   修正後: この設定は後から変更することができます。
```

- **選択肢には修正後の文そのものを書く。** 「簡潔にする」だけでは何がどう変わるか分からない —— UI が無い分、テキストで見比べられるかどうかが全て

## ステップ4: 方針の書き残し

決まった表記方針は `AGENTS.md` に残すことを提案する。ファイル種別でスコープできないため、**「Markdown 原稿を書くとき」のような適用条件を見出しか冒頭に明記する**よう促す。

`meta-skills` プラグインを入れているなら、`rule-creator` スキルにそのまま渡せる。
