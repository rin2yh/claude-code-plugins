# Codex でルールを書くとき

## 置き場所

SKILL.md の分類表の各行が、この環境ではどこに対応するか。

| SKILL.md の分類 | Codex での置き場所 |
|---|---|
| 常時読み込まれる規約ファイル | `~/.codex/AGENTS.md`（全プロジェクト）、リポジトリルートの `AGENTS.md` |
| 個別のルールファイル | 同じ `AGENTS.md` の1節、または特定ディレクトリの `AGENTS.md` |
| スキル | `skills/<name>/SKILL.md` |
| フック | Codex にも仕組みはあるが、このスキルでは扱わない |

Codex は作業対象に近い `AGENTS.md` から順に読み、上位ディレクトリのものと重ねて扱う。**「個別のルールファイル」に相当する独立ファイルは無く、ディレクトリを分けない限り `AGENTS.md` の一節になる。**

## Claude Code との最大の違い: パススコープが無い

`.claude/rules/` の `paths:` フロントマターにあたる仕組みが `AGENTS.md` には無い。**スコープを表現する手段は2つしかない。**

### 1. ディレクトリで絞る

規約が特定のディレクトリ配下だけに効けばいいなら、そのディレクトリに `AGENTS.md` を置く。これが最も確実で、Codex の想定どおりの使い方。

```
src/api/AGENTS.md    ← src/api 配下で作業するときだけ効く
```

### 2. 本文に適用条件を明記する

ファイル種別で絞りたい（`**/*.test.ts` だけ、など）場合、ディレクトリでは表現できない。**見出しと本文の冒頭に適用対象を書いて補う。**

```markdown
## テスト規約

適用対象: `**/*.test.ts`

（SKILL.md の例の箇条書きをそのまま）
```

「適用対象」の一行を省くと、**テストファイル以外にもテーブル駆動を持ち込まれる**。パススコープが機械的に効かない以上、条件は文章として読ませるしかない。

## 1ファイルに集約されることを前提に書く

`.claude/rules/` はトピックごとにファイルを分けられるが、`AGENTS.md` は1ディレクトリ1ファイル。既存の `AGENTS.md` に**追記**する形になるのが普通で、新規ファイルを作る場面はディレクトリを分けるときだけ。

そのため:

- 見出しレベルは `##` から始める（`#` はファイル全体のタイトル用に空けておく）
- 既に同じトピックの節があれば、新しい節を足さずそこに追記する
- 節が増えて読みにくくなったら、ディレクトリ単位で切り出せないか検討する

## 検証

- 追記後の `AGENTS.md` 全体を読み直し、既存の節と矛盾していないか確認する
- ファイル種別で絞ったつもりの規約に「適用対象」の記載が漏れていないか確認する
- 上位ディレクトリの `AGENTS.md` や `~/.codex/AGENTS.md` と衝突していないか見る
